## 本轮实际补强

- 核验凭据交付：新增 `verify_with_receipt` 和 CLI `--receipt`，从同一次核验绑定精确种子 SHA-256、infohash、完整真实文件映射、实际检查范围、观测大小和结果。
- 兼容与范围：旧核验 JSON、HTML 接口和退出码保持可用；凭据明确区分全量通过、局部通过和失败，不将相邻文件的部分检查解释为全文件通过。普通 JSON 不提供数字签名或发布者认证。
- 快照和输出保护：复制调用方大小映射，返回前捕获不可变文本；预检所有报告目标，避免覆盖、重复或写成缺失载荷；读后发现源文件变化时不写凭据或 HTML。多个输出依次写入，非原子事务。
- 复现证据：双后端测试覆盖快照修改隔离、范围、缺失空文件与详情截断；新增 27 个真实文件场景对照 Python 完整摘要、libtorrent infohash/布局和输出保护。单遍读取及故障观测也同时导出凭据。
- 持续推进：下一项按文件汇总损坏/缺失/不可读与待处理范围，再设计进度/取消契约；见 [ROADMAP.md](ROADMAP.md)。继续保持公开 CI、Mooncakes 精确版本安装和匹配标签的闭环。

## 仍需如实说明的边界

- 本项目是离线元数据与完整性核验组件；未实现下载、做种或 Tracker 服务。演示和说明应保持已申报的离线工具范围。
- 兼容性采用明确安全子集；不声称支持全部历史扩展、任意文件属性或符号链接。具体约定见 API 文档。
- 源文件身份与时间信息检查不是原子快照，内容哈希不证明发布者身份；创建发布包时使用稳定文件。
- 当前证据来自合成负载、实际磁盘流程和独立实现比较，尚无广泛真实用户反馈或生产级长时间稳定性数据。
- 参赛者应亲自运行示例，能解释 v1/v2、虚拟补零、部分核验范围、错误处理和依赖来源。无需再次填表，但仍需保持 GitHub 与 Mooncakes 的实际版本一致。
