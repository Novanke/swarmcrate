## 本轮实际补强

- 大文件核验：混合格式从两遍读取改为一遍，真实字节同时进入两套哈希检查；虚拟补零仍由内部提供。成功完整核验时每个真实字节只读取一次，局部核验只读取选中的文件。
- 错误处理：瞬态错误、短读或超长返回同时使当前片的两套检查不可读，之后的片继续检查。保留稳定输入和确定性错误下的原有诊断顺序、片号、偏移、计数与详情上限。
- 核验独立性：主动修改元数据中的单套哈希，确认不会因另一套通过而误报成功。用已有的独立 v1、v2 核验流程作回归参照。
- 实际读取证据：互操作脚本观察真实 Node 文件读取，覆盖完整、局部、空文件选择及读取异常；不把回调计数当成实测吞吐率。
- 基准：与注册表 0.4.0 对照，8 MiB 示例读取量和回调数减半，但 CPU 耗时接近。新测量与历史测量分别记录，见 [performance.md](performance.md)。

## 仍需如实说明的边界

- 本项目是离线元数据与完整性核验组件；未实现下载、做种或 Tracker 服务。演示和说明应保持已申报的离线工具范围。
- 兼容性采用明确安全子集；不声称支持全部历史扩展、任意文件属性或符号链接。具体约定见 API 文档。
- 源文件身份与时间信息检查不是原子快照，内容哈希不证明发布者身份；创建发布包时使用稳定文件。
- 当前证据来自合成负载、实际磁盘流程和独立实现比较，尚无广泛真实用户反馈或生产级长时间稳定性数据。
- 参赛者应亲自运行示例，能解释 v1/v2、虚拟补零、部分核验范围、错误处理和依赖来源。无需再次填表，但仍需保持 GitHub 与 Mooncakes 的实际版本一致。
