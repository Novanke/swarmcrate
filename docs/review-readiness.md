## 本轮实际补强

- 核验 SDK 控制：新增 `verify_with_control` 与只含标量的进度快照，在起始、读取前后、每次哈希检查和最终化前协作取消。旧接口、标准输出和报告/凭据格式保持兼容。
- 取消不冒充结果：返回 `false` 及观察者错误均中止，不返回完整报告或凭据；包括所有检查已完成的最终阶段。普通读取错误仍是不可读分片，即使错误代码叫 `cancelled` 也不会误当观察者取消。
- 典型消费方：纯 MoonBit 示例双后端执行；Node 消费方在成功返回及来源复查后才独占写出凭据，取消无输出，示例退出码 3。见 [SDK 控制契约](sdk-control.md)。
- 真实限制：当前是同步核验检查点，不抢占阻塞 I/O、解析或序列化；未实现创建控制、浏览器事件循环/Worker 适配或断点恢复。完成计数不表示通过或已保存。
- 复现证据：新增五个核心测试块与 30 个真实文件 SDK 控制场景，覆盖每阶段取消/异常、失败读取后的观察者错误、计数、空/缺失文件、损坏、已有输出和读后变化；既有 215 个互操作场景继续通过。
- 持续推进：下一项设计创建 SDK 的进度与取消，见 [ROADMAP.md](ROADMAP.md)。每次功能更新继续保持公开 CI、Mooncakes 精确版本安装和匹配标签的闭环。

## 仍需如实说明的边界

- 本项目是离线元数据与完整性核验组件；未实现下载、做种或 Tracker 服务。演示和说明应保持已申报的离线工具范围。
- 兼容性采用明确安全子集；不声称支持全部历史扩展、任意文件属性或符号链接。具体约定见 API 文档。
- 源文件身份与时间信息检查不是原子快照，内容哈希不证明发布者身份；创建发布包时使用稳定文件。
- 当前证据来自合成负载、实际磁盘流程和独立实现比较，尚无广泛真实用户反馈或生产级长时间稳定性数据。
- 参赛者应亲自运行示例，能解释 v1/v2、虚拟补零、部分核验范围、错误处理和依赖来源。无需再次填表，但仍需保持 GitHub 与 Mooncakes 的实际版本一致。
